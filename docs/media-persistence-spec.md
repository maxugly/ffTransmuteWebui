# Media Persistence & Cache Architecture

> **Status:** Specification Phase
> **Category:** Core Architecture

## 1. Overview
The backend `app/media` system manages a content-addressable cache designed to prevent redundant work. When a video or image is loaded, it is hashed (blake2b). All metadata, history, first/last frame screenshots, and full-video frame thumbnail strips generated by the user are bundled directly with this hash.

Recently, different features (like the new Frame Scrubber) started drifting towards creating parallel cache directories (e.g., `media/frames/{hash}`). This specification corrects that drift: **All data related to a single media file must live exclusively inside its dedicated `by_hash/{content_hash}` directory.**

## 2. Directory Structure & Invariants
All cached artifacts for a specific clip must reside in:
`~/.cache/mtapi/media/by_hash/{content_hash}/`

**Strict Structure:**
```text
by_hash/{content_hash}/
├── record.json       # Core metadata (history, dimensions, paths, op tracking)
├── first.jpg         # Extracted first frame (absolute)
├── last.jpg          # Extracted last frame (absolute)
├── first.phash       # Perceptual hash of first frame
├── last.phash        # Perceptual hash of last frame
├── last.extract_v    # Versioning file for extraction changes
├── range_thumbs/     # On-demand single-frame JPEGs for Cut / working range
│   └── frame_000012.jpg   # 1-based frame index, zero-padded
└── frames/           # Full low-res strip for Frame Scrubber (optional, heavy)
    ├── frame_00001.jpg
    ├── frame_00002.jpg
    └── ...
```

### Invariants:
1. **No Parallel Caches:** Features MUST NOT create `~/.cache/mtapi/media/other_folder/`. They must use `by_hash/{content_hash}/`.
2. **Metadata Integrity:** `record.json` is the source of truth for the clip's history and relationships. If a clip was generated by an operation (e.g., Datamosh), the record tracks its `parent_hash`.
3. **Lazy Generation:** Artifacts like `first.jpg`, `range_thumbs/`, or the `frames/` strip are generated strictly on-demand, not proactively.
4. **Range vs absolute thumbs:**  
   - `first.jpg` / `last.jpg` → Video Pool library cards (`?which=first|last`).  
   - `range_thumbs/frame_XXXXXX.jpg` → working-range UI (`?frame=N`). See `video-image-pools-spec.md`.

## 3. Correcting the Frame Scrubber Drift
The `docs/frame-scrubber-spec.md` previously specified storing thumbnails in `~/.cache/mtapi/media/frames/{content_hash}/`. 

**Correction:** 
- The Frame Scrubber must generate and store its JPEGs in `BY_HASH_DIR / {content_hash} / "frames"`.
- The GET endpoint serving these thumbnails must map `/media/frame-strip/{hash}/frame_{n}.jpg` directly to `by_hash/{hash}/frames/frame_{n}.jpg`.

## 4. Derived & Generated Media
When a pipeline operation (e.g., DeepDream) generates a *new* video, that new video is treated as an entirely separate entity with its own `content_hash`.
- The backend hashes the new `.mp4`.
- A new `by_hash/{new_hash}/record.json` is created.
- The `history` block in the new `record.json` logs the exact operation and the `parent_hash` of the original clip.
- Any subsequent UI actions on the *new* video (e.g., opening it in the viewer, generating a frame scrubber strip) will store artifacts in `by_hash/{new_hash}/`.

## 5. Garbage Collection
Because everything is bundled under a single directory per hash, the media cache garbage collector (which removes orphaned or old files when disk limits are reached) can simply delete the entire `by_hash/{content_hash}` directory. It will safely take the `record.json`, first/last thumbs, `range_thumbs/`, and the full frame strip down with it in one pass, leaving zero orphaned assets.

## 6. Session pool / project files (dual libraries)

Separate from content-addressed media cache:

| File | Role |
|------|------|
| `~/.cache/mtapi/pool_state.json` | Session autosave: videos `items[]` + stills `images[]` + sequence |
| `*.ffproject.json` | Named project (same pool payload; load preferred over session on startup) |

- Payload **version 2** includes `images[]` and `selected_image_path`.  
- Frontend dual-saves open project when pool changes (`js/pool/persistence.js`).  
- Full as-built: **`docs/video-image-pools-spec.md`**.

## 7. Implementation notes (thumbs)

| Helper / route | Role |
|----------------|------|
| `app/media/thumbnails.py` → `get_thumb_file` | Absolute first/last |
| `extract_frame_at` / `get_frame_thumb_file` | 1-based frame N → `range_thumbs/` |
| `GET /api/thumbnail?which=` | Absolute |
| `GET /api/thumbnail?frame=` | Working range |
| `app/media/config.py` → `_frames_dir` | Frame-scrubber strip dir |
| Frame-strip routes | `app/routes/media.py` under `/media/frame-strip/…` |
