# Stable Fluids — WebGL Sim Tab

> **Status:** **Proposed** — not implemented
> **Audience:** Builder assigned this job
> **Decision (human):** self-host only (**Path B** via `wget --mirror`). No external iframe fallback. Same-origin is required for recording.
> **Related:** `pool-wall-preview-spec.md` (Image Pool stills), `video-image-pools-spec.md` (dual pools, send-to), `agent-vision-tab-spec.md` (non-job tab pattern), `AGENTS.md` invariants (§6: one JPEG wall, never clear `img.src`)
> **Not this:** The StableFluids Unity project source. No server-side fluid simulation. No OpenVINO / filter-platform dump-encode path for the sim itself (recording uses `canvas.captureStream`, not ffmpeg).

---

## 1. Goal

Add a new **Stable Fluids** tab that embeds keijiro's WebGL fluid simulation 100% client-side in an `<iframe>`. The tab exposes:

1. The live WebGL canvas (60fps, GPU-accelerated, no server compute).
2. A **Record** button that captures the canvas via `canvas.captureStream` + `MediaRecorder` and downloads a `video/webm;codecs=vp9` blob.
3. **Optional (Phase 2):** a pure WebGPU port of the 3 compute shaders (~200 lines of JS, no Unity wasm) so the sim runs natively in the SPA without an iframe — enabling direct image injection as the initial color field.
4. **Optional (Phase 3):** inject an orange Image Pool still as the sim's starting state.

This is a **non-job tab** — like `imgcompare`, `agent`, and `settings`. It has no server-side `/ops/` endpoint, no Run/Queue, and no job token. It renders a form directly into `#actionPanelForm`.

## 2. Static file serving (the WebGL build)

### 2.1 The artifact — no Unity needed

Keijiro already built the WebGL demo and hosts it as a static site at:

```
https://keijiro.github.io/StableFluids/
```

It is plain static files — `index.html` + wasm + js + data. No Unity editor is required to use it. We **self-host** it locally (Path B) so the iframe is same-origin, which is required for `canvas.captureStream()` recording.

The old Pages URL (`keijiro.github.io/StableFluids/`) has been retired and redirects to a stub — the live build now lives at `www.keijiro.tokyo/StableFluids/`. Self-hosting it:

```bash
wget --mirror --convert-links http://www.keijiro.tokyo/StableFluids/
```

> **Why the mirror alone is not enough:** the three payload URLs (`*.data`, `*.framework.js`, `*.wasm`, all `.unityweb`) are assembled in JS (`createUnityInstance(config)` on the page), not in the HTML — so wget's link scan cannot discover them. Fetch them by hand:

```bash
cd StableFluids/Build
for f in StableFluids.data.unityweb StableFluids.framework.js.unityweb StableFluids.wasm.unityweb; do
  wget "http://www.keijiro.tokyo/StableFluids/Build/$f"
done
wget https://cdn.simplecss.org/simple.min.css -O ../simple.min.css
# copy the resulting folder into app/static/stablefluids/
```

The copied `index.html` must reference the local `simple.min.css` (rewrite the CDN link) — the artifact should be fully offline, no external resources.

```
mtapi-project/app/static/
├── index.html
├── app.js
├── css/
├── js/
└── stablefluids/
    ├── index.html
    ├── TemplateData/
    └── Build/
        ├── UnityLoader.js
        ├── WebGL.json / .wasm
        ├── *.data
        └── ...
```

**Rule:** the self-hosted folder is a checked-in artifact, not regenerated by the webui. The iframe `src` is always `/stablefluids/index.html` (same-origin). If the folder is not yet dropped, the tab shows a friendly placeholder with the `wget` command rather than loading an external URL.

### 2.2 FastAPI route

The existing `static.py` only serves `/css/{path}` and `/js/{path}` via `PlainTextResponse(read_text(...))` — that breaks on binary `.wasm`/`.data` files. The WebGL build has mixed binary + text assets and deep relative paths, so we use a `StaticFiles` mount (standard FastAPI, handles all MIME types natively):

**Spec:** register a `StaticFiles` mount at `/stablefluids`:

```python
# app/routes/static.py
from fastapi.staticfiles import StaticFiles

def register(app: FastAPI) -> None:
    ...
    build_static_dir = STATIC_DIR / "stablefluids"
    if build_static_dir.is_dir():
        app.mount("/stablefluids", StaticFiles(directory=str(build_static_dir), html=True), name="stablefluids")
```

- `html=True` so `/stablefluids/` serves `index.html` automatically.
- Guard with `is_dir()` — if the folder isn't present, skip the mount silently. The tab renderer checks this via a HEAD fetch and shows a placeholder with build instructions (see §4.2).
- No path-traversal risk: `StaticFiles` resolves safely under the mount root.

### 4.3 `state.stableFluids`

Add a tiny state slice in `app.js`:

```js
stableFluids: {
  recording: false,        // boolean — currently capturing
  buildReady: false,        // false until iframe signals canvas found
  recordButton: null,       // cached DOM ref
}
```

### 4.4 Iframe canvas discovery (same-origin)

The iframe serves from the same origin (`/stablefluids`) and the parent **can** reach into the iframe document. keijiro's build writes a `<canvas>` at runtime via Unity's WebGL loader, so we poll. Although we are same-origin, wrap access in try/catch as defensive hygiene — any future switch to an external URL would throw a `DOMException` (SecurityError) instead of returning null:

```js
function waitForCanvas(iframe, onFound) {
  const tryFind = () => {
    try {
      const doc = iframe.contentDocument;
      if (!doc) { setTimeout(tryFind, 100); return; }
      const canvas = doc.querySelector('canvas');
      if (canvas) { onFound(canvas); state.stableFluids.buildReady = true; }
      else { setTimeout(tryFind, 100); }
    } catch (e) {
      // Defensive: cross-origin would land here. Not expected on Path B.
      state.stableFluids.buildReady = false;
    }
  };
  tryFind();
}
```

Cache the canvas ref so we don't re-poll. **Never** clear `src` on the iframe (AGENTS.md §6: never clear `img.src`/`iframe.src` because a shell might be reused).

## 5. Recording (Phase 1 — iframe + captureStream)

### 5.1 The approach

Per the user's recipe, adapted for the iframe's canvas. Works because we self-host (same-origin):

```js
let recChunks = [];
let mediaRecorder = null;

function startRecording(canvas) {
  // 60fps capture from the GPU-rendered WebGL canvas
  const stream = canvas.captureStream(60);
  mediaRecorder = new MediaRecorder(stream, {
    mimeType: 'video/webm;codecs=vp9',
    videoBitsPerSecond: 25_000_000,
  });
  recChunks = [];
  mediaRecorder.ondataavailable = e => recChunks.push(e.data);
  mediaRecorder.onstop = () => {
    const blob = new Blob(recChunks, { type: 'video/webm' });
    const a = document.createElement('a');
    a.href = URL.createObjectURL(blob);
    a.download = `fluid_${Date.now()}.webm`;
    a.click();
    URL.revokeObjectURL(a.href);
    finishRecordUi();
  };
  mediaRecorder.start();
}

function stopRecording() {
  if (mediaRecorder && mediaRecorder.state === 'recording') {
    mediaRecorder.stop();
  }
}
```

### 5.2 Record button wiring

```js
btnRecord.onclick = () => {
  if (state.stableFluids.recording) {
    stopRecording();
  } else {
    const canvas = cachedCanvasRef;
    if (!canvas) { alert('Fluid canvas not ready yet…'); return; }
    startRecording(canvas);
    state.stableFluids.recording = true;
    btnRecord.textContent = 'Stop';
  }
};
```

### 5.3 Output handling

- Recorded WebM lands in the browser's default download folder (not the pool). The user can then import it into the Video Pool.
- **Alternative (frame-perfect):** swap `MediaRecorder` for CCapture.js to dump per-frame PNG sequence and package the result as a **`.zip`** that downloads locally to the browser (matching the WebM download behavior — no server workspace). CCapture.js is only available in WebGPU native mode (Phase 2), where direct canvas access exists without the iframe boundary. The `frame_%06d.png` naming matches the filter-platform convention (AGENTS.md §1) for consistency, even though these frames never pass through `app/filters/*`. Not a Phase 1 requirement.

### 5.4 Constraints

- `captureStream` requires the canvas to be **same-origin** (satisfied — we serve the build ourselves).
- VP9 in WebM is broadly supported in Chromium; Firefox may need `video/webm` fallback. Spec: try VP9, fall back to `video/webm` (no codec) if `MediaRecorder.isTypeSupported` rejects it.
- 25 Mbps is the user's suggested bitrate; expose as a hidden pref, default `25_000_000`.

## 6. Phase 2 — Pure WebGPU native port (no iframe)

### 6.1 When to build

When the user wants to:
- Eliminate Unity wasm bloat (~5–10 MB download → ~200 lines of JS).
- Inject images directly as the initial color field.
- Capture PNG sequences frame-perfect via CCapture.js.

### 6.2 What it is

A standalone `stablefluids_webgpu.js` (~200 lines) that ports keijiro's three WebGL compute passes to **WebGPU compute shaders**:

| Pass | WebGL | WebGPU port |
|------|-------|-------------|
| Advection | fragment shader | compute, read/write texture |
| Divergence | fragment shader | compute |
| Gradient subtract / pressure projection | fragment shader | compute |

The port:
- Uses a single `<canvas id="stablefluids-canvas" />` in the tab (no iframe).
- 512×512 default canvas (configurable).
- Same mouse interaction (velocity injection) via pointer events.
- **Initial color:** accepts an image URL at construction, uploads as the `uTex` texture so the sim starts from the user's still instead of black.

### 6.3 Integration

If `state.stableFluids.mode === 'webgpu'` and the browser supports `navigator.gpu`, render the WebGPU canvas directly in `#actionPanelForm`. Otherwise fall back to the iframe.

The mode toggle lives in the `.tool-docs` section: **"WebGL (iframe)"** vs **"WebGPU (native)"** — default to WebGL iframe for v1 (lowest risk; just embed the existing build).

### 6.4 Files

| File | Role |
|------|------|
| `js/tabs/stablefluids.js` | Tab renderer, iframe + record, mode toggle |
| `js/stablefluids_webgpu.js` | Pure WebGPU port (~200 lines, standalone, ES6 module) |

## 7. Phase 3 — Image injection ("orange" start frame)

### 7.1 Product

Start the fluid sim from the user's first Image Pool still instead of a black field. This gives the "orange" color field a starting texture — the simulation then advects and reacts to that image.

### 7.2 Sources (priority order)

1. **Dedicated image path** — a new `#sfSeedImage` text + Browse row in the tab.
2. **Image Pool first selection** — if the path field is blank, call `resolveGlobalImages()[0]` (the first line of the Image Pool bar). This matches the QR Illusion pattern where `#giImage` lines feed Pattern + Appearance.
3. **Fallback** — black (current sim default).

### 7.3 Injection mechanics

| Mode | How |
|------|-----|
| **WebGL iframe** | Not possible with the stock keijiro build — it does not listen for `postMessage`. Image injection is **Phase 3 WebGPU-only** unless the user forks the Unity build to add a message listener. |
| **WebGPU native** | Set `initialTextureUrl = path` in `stablefluids_webgpu.js` before the first `animate()` frame. Upload to GPU texture via `device.createTexture` + `copyBufferToTexture`. |

### 7.4 UI

- The seed image row is shown **always**, but disabled/hinted when in WebGL-iframe mode (tooltip: "Requires WebGPU native mode").
- After a recording or PNG-sequence capture, add the seed image as a still-frame reference in the Image Pool (optional, separate ticket).

## 11. Out of scope

- Modifying the keijiro StableFluids WebGL build or its shader logic.
- Running Unity to rebuild (we use the pre-built static artifact).
- External-URL iframe fallback (www.keijiro.github.io). The sim is always self-hosted locally.
- Server-side fluid simulation (no `/ops/stablefluids` endpoint).
- OBS / screen recorder integration.
- Image injection in the default WebGL-iframe mode (Phase 3 / WebGPU only).
- Multiple simultaneous sim instances or sim parameter tuning (the Unity UI already exposes these).
- WebP or AVIF output for recordings (WebM only).
- Integrating the recording as a Video Pool item automatically (import is manual via browse/upload).
