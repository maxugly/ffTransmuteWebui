# Audio-Reactive Video Processing

> **Status:** Spec Drafted (Not Implemented)

## Overview
A suite of effects that manipulate video playback and visuals based on the underlying audio track's musical characteristics (beats, transients, pitch, and loudness). This turns static or linear video into a reactive, music-video-style edit automatically.

## Pipeline Architecture
- **Engine**: `librosa` (Pure Python/NumPy audio analysis).
- **Pattern**: 
  1. FFmpeg extract audio track to temporary `.wav`.
  2. `librosa` analyzes audio array and generates a time-series event map.
  3. `PngFramePipeline` dumps video frames.
  4. Script maps each video frame to the audio time-series and applies the requested transformations.
  5. FFmpeg re-encodes with the original audio.

## Knobs & Parameters

### 1. Transient / Beat Stutter (Rhythm)
Detects sharp attacks (drums) or musical beats.
- `beat_sync_mode`: `none`, `stutter` (repeats the transient frame), `flash` (flashes a color/invert on beat), `skip` (skips frames between beats to speed up).
- `onset_sensitivity`: Float (controls how aggressive the transient detection is).

### 2. Loudness-Driven Zoom (Dynamics)
Uses RMS energy to physically scale the video frame.
- `loudness_zoom`: Float (Multiplier. e.g., 1.2 = zoom in 20% when the bass hits).
- `zoom_smoothing`: Float (Damping factor so the zoom doesn't jitter crazily).

### 3. Pitch-Dependent Color (Harmony)
Uses chroma features or fundamental frequency (YIN algorithm) to shift hue.
- `pitch_effect`: `none`, `hue_shift` (rotates color wheel based on pitch), `saturation_pump` (increases color intensity on high pitches).
- `pitch_sensitivity`: Float.

## Integration Notes
- `librosa` runs entirely on the CPU and is heavily optimized via NumPy. It will scream on Iris Xe hardware.
- Time-sync is critical. The script must carefully map `frame_index / fps` to the `audio_time_seconds` array generated by `librosa.times_like`.
- **Destructive timeline:** Features like "stutter" change the total frame count of the video. The final FFmpeg encode step must be careful to match the modified video length with the audio, or the audio must also be stuttered (which is much harder). A safer MVP is to strictly modify the visual frames (zoom, flash, hue) or freeze frames without changing the total duration, keeping audio sync trivial.
